# HomeDishPicker 家常菜抽签系统

一个用于练习前端基础、Codex、Git、README 和版本控制的小项目。

## 项目目标

制作一个网页版家常菜随机抽签系统，帮助用户快速决定今天吃什么。

## 第一版功能

- 展示家常菜候选列表
- 点击按钮随机抽取一道菜
- 显示抽签结果
- 支持重复抽取

## 第二版功能

- 抽签时显示菜名滚动，最后定格到抽中的菜
- 输入冰箱现有食材，根据食材推荐可做菜品
- 抽签时优先从匹配食材的菜品中抽选
- 支持添加自己会做的菜到抽签库
- 自定义菜品会保存在当前浏览器中
- 每道菜都提供小红书教程搜索入口

## 第三版功能

- 添加菜品时，输入常见菜名会自动补充需要的食材
- 新增“随机发现一道菜”，用于尝试抽签库以外的新菜灵感
- 新菜灵感和抽签结果都提供小红书教程搜索入口
- 抽签库按菜品分类折叠展示，减少页面滚动长度
- 冰箱食材匹配结果会在抽签库卡片中显示

## 当前版本

v3 已完成食材推荐、自定义菜品、自动补充食材、滚动抽签、新菜灵感和折叠分类展示。页面可以直接在浏览器中运行，不需要安装依赖。

## 如何运行

直接用浏览器打开 `index.html`。

如果要在手机上使用，需要把整个项目文件夹一起发送到手机，并保持下面的目录结构不变：

```text
HomeDishPicker/
├── index.html
├── css/
│   └── style.css
└── js/
    └── app.js
```

只发送 `index.html` 一个文件是不够的，因为页面还需要读取 CSS 和 JavaScript 文件。

## 如何使用

### 从我会做的菜里抽签

1. 打开 `index.html`。
2. 点击“抽一道菜”。
3. 菜名会滚动一小段时间，然后定格到最终结果。
4. 点击“小红书教程”可以查看对应菜品的教程搜索结果。

### 根据冰箱食材推荐

1. 在“冰箱食材”输入框中填写已有食材。
2. 多个食材可以用顿号、逗号、空格或换行分隔。
3. 系统会优先从匹配食材的菜品中抽选。
4. 抽签库卡片会显示当前菜品是否匹配已有食材。

### 添加我会做的菜

1. 在“添加我会做的菜”区域输入菜名。
2. 如果菜名在系统的新菜灵感池中，食材会自动补充。
3. 食材仍然可以手动修改。
4. 点击“添加到抽签库”后，菜品会保存到当前浏览器中。

### 随机发现新菜

1. 点击“随机挑一道新菜”。
2. 系统会从已有抽签库和新菜灵感池中随机选择。
3. 适合在想尝试新菜、不想只吃熟悉菜品时使用。

## 数据保存说明

当前项目没有后端，也没有数据库。自定义菜品保存在浏览器的 `localStorage` 中。

这意味着：

- 刷新页面后，自定义菜品仍然存在。
- 换一个浏览器打开，自定义菜品不会自动同步。
- 清理浏览器缓存或网站数据后，自定义菜品可能会丢失。
- 之后可以通过“导入和导出抽签库”功能解决备份和迁移问题。

## 推荐 Commit 划分

本项目第一版按照以下思路拆分提交：

- `chore: initialize project files`
- `docs: add initial README`
- `feat: add basic page structure`
- `style: add page layout and visual styles`
- `feat: implement random dish picker`
- `docs: update README with v1 usage`

后续版本可以继续按功能拆分提交：

- `feat: add quick ingredient tags`
- `feat: add no-repeat draw mode`
- `feat: add draw history`
- `feat: support editing custom dishes`
- `feat: support importing and exporting dish library`
- `docs: update roadmap and usage guide`

建议每个 commit 只解决一个清晰问题。例如“添加快捷食材标签”和“新增历史记录”应该分开提交，这样以后查看版本历史会更容易。

## 当前限制

- 小红书教程目前是搜索结果链接，不是固定教程内容。
- 新菜灵感池是项目内置数据，不是实时从小红书抓取。
- 自定义菜品只保存在当前浏览器，暂时不能跨设备同步。
- 目前没有删除和编辑功能，添加错了需要等后续版本完善。
- 当前项目是纯静态页面，适合练习前端基础和 Git 工作流。
