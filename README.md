# HomeDishPicker 家常菜抽签系统

一个用于练习前端基础、Codex、Git、README 和版本控制的小项目。

## 项目目标

制作一个网页版家常菜随机抽签系统，帮助用户快速决定今天吃什么。

## 第一版功能

- 展示家常菜候选列表
- 点击按钮随机抽取一道菜
- 显示抽签结果
- 支持重复抽取

## 第二版功能

- 抽签时显示菜名滚动，最后定格到抽中的菜
- 输入冰箱现有食材，根据食材推荐可做菜品
- 抽签时优先从匹配食材的菜品中抽选
- 支持添加自己会做的菜到抽签库
- 自定义菜品会保存在当前浏览器中
- 每道菜都提供小红书教程搜索入口

## 第三版功能

- 添加菜品时，输入常见菜名会自动补充需要的食材
- 新增“随机发现一道菜”，用于尝试抽签库以外的新菜灵感
- 新菜灵感和抽签结果都提供小红书教程搜索入口
- 抽签库按菜品分类折叠展示，减少页面滚动长度
- 冰箱食材匹配结果会在抽签库卡片中显示

## 当前版本

v4 已完成快捷食材、不重复抽取、抽签历史、自定义菜品编辑删除、导入导出、重置数据、新菜分类筛选和推荐等级展示。页面可以直接在浏览器中运行，不需要安装依赖。

## 部署到 GitHub Pages

这个项目是纯静态网页，不需要服务器和构建工具，适合直接部署到 GitHub Pages。

部署完成后，可以通过类似下面的网址访问：

```text
https://你的GitHub用户名.github.io/HomeDishPicker/
```

### 第一步：在 GitHub 创建远程仓库

1. 登录 GitHub。
2. 点击右上角 `+`，选择 `New repository`。
3. 仓库名建议填写 `HomeDishPicker`。
4. 选择 `Public`，这样 GitHub Pages 更方便公开访问。
5. 不要勾选 `Add a README file`，因为本地项目里已经有 README。
6. 点击 `Create repository`。

### 第二步：把本地仓库连接到 GitHub

在项目目录中打开终端，确认当前目录是项目根目录：

```bash
pwd
```

当前项目路径是：

```text
E:\AI项目\家常菜抽签系统20260517
```

如果 GitHub 给你的远程仓库地址是：

```text
https://github.com/你的GitHub用户名/HomeDishPicker.git
```

则执行：

```bash
git remote add origin https://github.com/你的GitHub用户名/HomeDishPicker.git
```

如果已经添加过 `origin`，可以用下面的命令查看：

```bash
git remote -v
```

如果地址填错了，可以改成正确地址：

```bash
git remote set-url origin https://github.com/你的GitHub用户名/HomeDishPicker.git
```

### 第三步：推送代码到 GitHub

当前本地分支是 `master`，所以可以执行：

```bash
git push -u origin master
```

推送成功后，刷新 GitHub 仓库页面，应该能看到这些文件：

```text
index.html
css/style.css
js/app.js
README.md
.gitignore
```

### 第四步：开启 GitHub Pages

1. 打开 GitHub 上的 `HomeDishPicker` 仓库。
2. 点击 `Settings`。
3. 在左侧菜单中找到 `Pages`。
4. 在 `Build and deployment` 区域中找到 `Source`。
5. 选择 `Deploy from a branch`。
6. 在 `Branch` 中选择 `master`。
7. 文件夹选择 `/(root)`。
8. 点击 `Save`。

等待几十秒到几分钟后，GitHub Pages 会生成访问地址。

项目地址通常是：

```text
https://你的GitHub用户名.github.io/HomeDishPicker/
```

### 第五步：验证部署结果

打开 GitHub Pages 生成的网址，检查：

- 页面能正常打开。
- 样式正常加载。
- 点击“抽一道菜”有滚动定格效果。
- “随机挑一道新菜”可以显示结果。
- 小红书教程链接可以跳转。
- 手机浏览器访问页面时布局正常。

### 后续如何更新线上版本

以后每次修改项目后，按下面流程更新线上页面：


### 常见问题

- 如果访问地址显示 404，先确认 Pages 的发布源是否选择了 `master` 和 `/(root)`。
- 如果页面有内容但没有样式，检查 `index.html` 中是否正确引用了 `css/style.css`。
- 如果按钮没有反应，检查 `index.html` 中是否正确引用了 `js/app.js`。
- 如果刚刚开启 Pages 后打不开，等待几分钟再刷新。
- 如果仓库名不是 `HomeDishPicker`，访问地址中的最后一段也要换成实际仓库名。

## 如何使用

### 从我会做的菜里抽签

1. 打开 `index.html`。
2. 点击“抽一道菜”。
3. 菜名会滚动一小段时间，然后定格到最终结果。
4. 点击“小红书教程”可以查看对应菜品的教程搜索结果。

### 根据冰箱食材推荐

1. 在“冰箱食材”输入框中填写已有食材。
2. 多个食材可以用顿号、逗号、空格或换行分隔。
3. 系统会优先从匹配食材的菜品中抽选。
4. 抽签库卡片会显示当前菜品是否匹配已有食材。

### 添加我会做的菜

1. 在“添加我会做的菜”区域输入菜名。
2. 如果菜名在系统的新菜灵感池中，食材会自动补充。
3. 食材仍然可以手动修改。
4. 点击“添加到抽签库”后，菜品会保存到当前浏览器中。

### 随机发现新菜

1. 点击“随机挑一道新菜”。
2. 系统会从已有抽签库和新菜灵感池中随机选择。
3. 适合在想尝试新菜、不想只吃熟悉菜品时使用。
4. 如果抽到的新菜还不在抽签库中，可以点击“加入我的抽签库”保存。

### 管理抽签库

1. 自己添加的菜品支持编辑和删除。
2. 默认菜品作为基础数据保留，不能直接删除。
3. 每道菜可以保存分类、状态、备注和固定教程链接。
4. 抽签库会按分类折叠展示。

### 备份和恢复数据

1. 点击“导出抽签库 JSON”可以下载当前自定义菜品和历史记录。
2. 点击“导入抽签库 JSON”可以恢复之前导出的数据。
3. 点击“重置自定义数据”可以清空自定义菜品和抽签历史，默认菜品会保留。

### 不重复抽取和抽签历史

1. 勾选“开启不重复抽取”后，一轮抽完前不会重复抽到同一道菜。
2. 如果所有候选菜都抽过了，系统会自动开始新一轮。
3. 抽签历史会记录最近抽到的菜名、来源、时间和教程入口。

## 数据保存说明

当前项目没有后端，也没有数据库。自定义菜品保存在浏览器的 `localStorage` 中。

这意味着：

- 刷新页面后，自定义菜品仍然存在。
- 换一个浏览器打开，自定义菜品不会自动同步。
- 清理浏览器缓存或网站数据后，自定义菜品可能会丢失。
- 之后可以通过“导入和导出抽签库”功能解决备份和迁移问题。

## 推荐 Commit 划分

本项目第一版按照以下思路拆分提交：

- `chore: initialize project files`
- `docs: add initial README`
- `feat: add basic page structure`
- `style: add page layout and visual styles`
- `feat: implement random dish picker`
- `docs: update README with v1 usage`

后续版本可以继续按功能拆分提交：

- `feat: add quick ingredient tags`
- `feat: add no-repeat draw mode`
- `feat: add draw history`

建议每个 commit 只解决一个清晰问题。例如“添加快捷食材标签”和“新增历史记录”应该分开提交，这样以后查看版本历史会更容易。
